Proxmox lab environment for IT trainees

Project by Özdem Tas · final project of my vocational training

For my IHK final project I planned and built a virtual lab environment in which IT trainees can practise Linux administration on their own isolated machines – safely separated from production systems, reachable from anywhere via VPN and without any licence costs.

At a glance

PlatformProxmox VE 9 on a single bare-metal server
Virtual machines8 lab VMs for trainees + 3 infrastructure VMs (DHCP, DNS, WireGuard)
TemplatesDebian, Ubuntu Server, AlmaLinux
Resources allocated64 GB RAM · 640 GB storage
AccessWireGuard VPN · role-based permissions (RBAC)
Licence costs€0
Project scope40 hours – from requirements to handover

Why this project?

Trainees learn Linux administration best by doing it: installing packages, configuring services, breaking things and fixing them again. That needs real systems – but practising on shared or production-adjacent machines is risky. The goal was a dedicated environment where every trainee has their own server to experiment with, while the rest of the network stays completely untouched.

Requirements

  • One separate VM per trainee, isolated from production networks
  • Secure remote access from outside
  • Trainees may only use their own VM – no access to others or to the host
  • New or reset VMs quickly provided from templates
  • Several Linux distributions for different training scenarios
  • Reuse of existing hardware, no licence costs

Choosing the platform

I compared Proxmox VE, VMware ESXi and XCP-ng using a five-year cost comparison and a weighted scoring model. Proxmox VE came out on top: no licence costs, a full web interface, a complete API for automation and built-in templates, firewall and permission system. The free ESXi edition is limited to non-production use without vCenter, and XCP-ng would have meant noticeably more setup effort.

Implementation

  1. Planning – requirements, IP concept and resource planning. CPU is deliberately overcommitted, because not all VMs run under full load at the same time.
  2. Installation – Proxmox VE installed remotely on the bare-metal server via the IPMI/KVM console.
  3. Network – isolated bridge vmbr1 without a physical port; internet access for the lab via NAT, selected services via DNAT.
  4. Infrastructure services – own VMs for DHCP, DNS (bind9 with forwarding) and the WireGuard VPN server.
  5. Templates & lab VMs – three Linux templates created, eight lab VMs cloned from them.
  6. Permissions – users, a resource pool and path-based RBAC: each trainee may only start, stop and open the console of their own VM.
  7. Security – Proxmox firewall activated as the last step: admin access only from the lab network or through the VPN.
  8. Testing & handover – functional tests of network, DNS, VPN and permissions, followed by a handover documentation for the support team.

Challenges & solutions

Activating the firewall without locking myself out

A wrong firewall rule on a remote server can cut off your own access. So I first tested WireGuard as a fallback route and checked NAT and DNAT together with the planned rules. Only then did I activate the firewall and verified web interface and SSH access again.

Fitting 11 VMs onto one server

Eight trainee VMs and three infrastructure VMs had to share the resources of one machine. I sized RAM and storage per VM so that everything fits fixed limits, and planned CPU with deliberate overcommitting – realistic for a training lab where machines are rarely under full load at once.

Result

  • Eight ready-to-use, isolated lab VMs based on Linux
  • Secure remote access for trainees via WireGuard VPN
  • Clear permissions: trainees cannot affect other VMs or the host
  • New VMs can be provided at any time from the templates
  • No licence or hardware costs

Next steps: an external backup target (currently backups are stored locally) and central monitoring of CPU, RAM and storage.

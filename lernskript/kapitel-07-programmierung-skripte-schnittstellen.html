7Programmierung, Skripte & Schnittstellen

Relevanz ★★★15–17 Punkte · größte EinzelaufgabeLernzeit ca. 2 × 150 min
AUF EINEN BLICK
  • Arrays beginnen bei Index 0. Letzter Index = Länge − 1. Schleife: i < array.Length , nie <= .
  • Die Prüfung fragt fast immer: Code ergänzen, Fehler finden, Trace-Tabelle ausfüllen.
  • Die sechs Grundmuster: Summe/Mittelwert · Maximum/Minimum · Zählen mit Bedingung · Suchen · Tauschen · neues Array befüllen.
  • / bei Ganzzahlen = ganzzahlige Division (7 / 2 = 3). % = Rest (7 % 2 = 1).
  • Maximum mit dem ersten Element initialisieren, nicht mit 0.
  • Skripte (PowerShell, Bash, Python) folgen derselben Logik; dazu APIs und Datenformate (JSON, XML).

Pseudocode-Syntax (so, wie sie die IHK verwendet)

Die IHK nutzt eine an Java/C# angelehnte Schreibweise. Kleine Abweichungen sind erlaubt, solange die Logik eindeutig ist. Präge dir diese Formen ein, dann brauchst du keinen Belegsatz:

// Variablen und Datentypen
int anzahl = 0                    // Ganzzahl
double summe = 0.0                // Kommazahl
string name = "Server01"          // Text
bool gefunden = false             // Wahrheitswert
// Arrays
int[] werte = new int[5]          // 5 Felder: Index 0 bis 4
int[] temp  = {21, 25, 19, 30}    // direkt befüllt
werte[0] = 12                     // erstes Element setzen
werte.Length                      // Anzahl der Elemente (hier 5)
// Verzweigung
if (wert > 80 && aktiv == true) {       // && = UND,  || = ODER,  ! = NICHT
    ausgabe("Warnung")
} else if (wert > 60) {
    ausgabe("Hinweis")
} else {
    ausgabe("OK")
}
// Zählschleife: Anzahl der Durchläufe bekannt
for (int i = 0; i < werte.Length; i++) { … }
// Kopfgesteuert: prüft vorher, läuft evtl. 0-mal
while (i < werte.Length && !gefunden) { … }
// Fußgesteuert: läuft mindestens 1-mal
do { … } while (eingabe < 0)
// Methode mit Rückgabewert
double berechneMittel(int[] a) { … return ergebnis }

Die sechs Grundmuster

Muster 1: Summe und Mittelwert

int summe = 0
for (int i = 0; i < werte.Length; i++) {
    summe = summe + werte[i]
}
double mittel = summe / werte.Length       // Achtung: ggf. in double umwandeln

Muster 2: Maximum (und Position)

int max = werte[0]                  // NICHT 0! (falsch, wenn alle Werte negativ)
int pos = 0
for (int i = 1; i < werte.Length; i++) {  // ab 1, Index 0 ist schon in max
    if (werte[i] > max) {
        max = werte[i]
        pos = i
    }
}

Muster 3: Zählen mit Bedingung (Schwellenwert)

int zaehler = 0
for (int i = 0; i < cpuLast.Length; i++) {
    if (cpuLast[i] > 80) {
        zaehler++
    }
}
if (zaehler > 3) { ausgabe("CPU-Last kritisch: " + zaehler + " Überschreitungen") }

Muster 4: Suchen (mit vorzeitigem Abbruch)

int i = 0
bool gefunden = false
while (i < ips.Length && !gefunden) {
    if (ips[i] == gesuchteIP) { gefunden = true }
    else { i++ }
}
// gefunden == true → Treffer an Index i

Muster 5: Tauschen

// Tauschen braucht eine Hilfsvariable
int temp = a[j]
a[j] = a[j + 1]
a[j + 1] = temp

Muster 6: Neues Array befüllen (z. B. Glättung)

// Mittelwerte aus je drei aufeinanderfolgenden Messwerten (gleitender Mittelwert)
double[] glatt = new double[mess.Length - 2]
for (int i = 0; i < mess.Length - 2; i++) {
    glatt[i] = (mess[i] + mess[i + 1] + mess[i + 2]) / 3.0
}

Checkliste für Fehlersuche-Aufgaben:

☐ Startwert der Schleife: 0 oder 1? Wird Index 0 übersprungen?

☐ Endbedingung: < statt <= ? Bei Zugriff auf [i+1] : < Length - 1 ?

☐ Initialisierung: Summe/Zähler = 0 vor der Schleife? Maximum = erstes Element?

☐ Werden Variablen in einer äußeren Schleife korrekt zurückgesetzt?

☐ Vergleichsoperator richtig ( > / >= , == statt = )?

☐ Ganzzahldivision beim Mittelwert? Division durch 0 möglich (leeres Array)?

☐ Wird die richtige Variable ausgegeben bzw. zurückgegeben?

Skripte: wiederkehrende Abläufe automatisieren

Der FISI-Katalog verlangt ausdrücklich, Systemabläufe mit PowerShell, Bash oder Python zu automatisieren und zu überwachen. In der Prüfung heißt das meist: ein kurzes Skript lesen, erklären, ergänzen oder einen Fehler finden. Die Logik ist dieselbe wie beim Pseudocode.

PowerShell (Windows): Warnung bei wenig freiem Speicher

$grenze = 10                                          # Prozent
Get-Volume | Where-Object { $_.DriveLetter } | ForEach-Object {
    $frei = [math]::Round($_.SizeRemaining / $_.Size * 100, 1)
    if ($frei -lt $grenze) {                          # -lt = kleiner als
        Write-Output "WARNUNG: Laufwerk $($_.DriveLetter): nur $frei % frei"
    }
}

PowerShell-Vergleiche: -eq gleich · -ne ungleich · -lt / -le kleiner (gleich) · -gt / -ge größer (gleich). Variablen beginnen mit $ , die Pipeline | reicht Objekte weiter.

Bash (Linux): tägliches Backup mit Aufräumen

#!/bin/bash
# Sichert /etc als Archiv und löscht Sicherungen, die älter als 7 Tage sind
ZIEL="/backup"
DATUM=$(date +%F)                                   # z. B. 2026-11-25
tar -czf "$ZIEL/etc-$DATUM.tar.gz" /etc
find "$ZIEL" -name "etc-*.tar.gz" -mtime +7 -delete

Zeitgesteuert per cron ( crontab -e ): 0 2 * * * /usr/local/bin/backup.sh = täglich um 2:00 Uhr. Die fünf Felder: Minute · Stunde · Tag · Monat · Wochentag. Unter Windows übernimmt das die Aufgabenplanung. Das Skript muss ausführbar sein ( chmod +x ).

Python: Erreichbarkeit mehrerer Hosts prüfen

import subprocess
hosts = ["10.0.0.1", "10.0.0.10", "8.8.8.8"]
for h in hosts:
    ok = subprocess.run(["ping", "-c", "1", h], capture_output=True).returncode == 0
    print(h, "erreichbar" if ok else "NICHT erreichbar")

Gute Skripte: Kommentare, Variablen statt fest eingetragener Werte, Fehlerbehandlung, Protokollierung (Logdatei), keine Passwörter im Klartext, vorher in der Testumgebung ausführen.

Schnittstellen und Datenformate

  • API (Application Programming Interface): definierte Schnittstelle, über die Programme miteinander kommunizieren. Heute meist REST über HTTPS mit JSON: GET (lesen), POST (anlegen), PUT / PATCH (ändern), DELETE (löschen). Absicherung per API-Key/Token und TLS. Beispiele: Redfish (Serververwaltung, Kapitel 1), Proxmox-API.
FormatBeispiel (derselbe Datensatz)Eigenschaften

Programmiersprache auswählen

Kompiliert (C, C++, Go: schnell, plattformabhängige ausführbare Datei) · Interpretiert (Python, PowerShell, Bash: kein Übersetzungsschritt, ideal für Automatisierung) · Bytecode/Laufzeitumgebung (Java, C#: portabel). Kriterien laut Katalog: Aufwand, Know-how im Team, verfügbare Frameworks/Bibliotheken, Performance und Speicherverbrauch, Portabilität, Entwicklungsumgebung (IDE).

Kompatibilität: Zeichensätze

ASCII (7 Bit, 128 Zeichen, keine Umlaute) · ISO-8859-1/Latin-1 (8 Bit, westeuropäische Umlaute) · Unicode/UTF-8 (1–4 Byte pro Zeichen, alle Schriftzeichen, heutiger Standard). Typischer Fehler: Eine UTF-8-Datei wird als Latin-1 gelesen → aus „ä“ wird „Ã¤“. Lösung: Kodierung auf beiden Seiten einheitlich festlegen. Zeilenenden unterscheiden sich ebenfalls: Windows CRLF, Linux LF (Skripte von Windows laufen unter Linux dann evtl. nicht).

Kompatibilität: typische Probleme beim Datenaustausch und Betrieb sind Dezimaltrennzeichen und Datumsformat (CSV-Import), Zeichensätze, 32- oder 64-Bit-Versionen und fehlende bzw. falsche Versionen von Bibliotheken und Laufzeitumgebungen. OpenData = frei nutzbare öffentliche Datensätze (z. B. Wetter-, Verkehrs- oder Geodaten), meist per REST-API als JSON oder CSV abrufbar.

Objektorientierung (Grundbegriffe)

  • Klasse: Bauplan (z. B. Server ) mit Attributen (Hostname, RAM) und Methoden (starten(), neustarten()).
  • Objekt: konkrete Instanz einer Klasse ( Server web01 = new Server("web01") ).
  • Kapselung: Attribute sind private ; Zugriff nur über öffentliche Methoden (Getter/Setter), die Eingaben prüfen können. Schützt vor ungültigen Werten.
  • Vererbung: Unterklasse übernimmt Attribute und Methoden der Oberklasse und erweitert sie ( Datenbankserver erbt von Server ).

Vorteile von Pseudocode: unabhängig von einer Programmiersprache, konzentriert auf die Logik, auch für Nicht-Programmierer lesbar. Testverfahren: siehe Kapitel 8.

6Datenbanken & SQL

Relevanz ★★★10–15 Punkte · seit Katalog 2025 nur noch in der AP2Lernzeit ca. 180 min
AUF EINEN BLICK
  • Primärschlüssel (PK) identifiziert eine Zeile eindeutig. Fremdschlüssel (FK) verweist auf den PK einer anderen Tabelle.
  • m:n-Beziehungen werden über eine Zwischentabelle mit zwei Fremdschlüsseln aufgelöst.
  • 3. Normalform: atomare Werte (1NF), alles hängt vom ganzen Schlüssel ab (2NF), keine Abhängigkeit zwischen Nicht-Schlüssel-Spalten (3NF).
  • Reihenfolge einer Abfrage: SELECT … FROM … JOIN … WHERE … GROUP BY … HAVING … ORDER BY .
  • WHERE filtert Zeilen vor der Gruppierung, HAVING filtert Gruppen danach.

Das relationale Modell

Daten liegen in Tabellen (Relationen). Eine Zeile ist ein Datensatz (Tupel), eine Spalte ein Attribut. Tabellen werden über Schlüssel verknüpft.

  • Primärschlüssel: eindeutig, nie leer (NOT NULL). Oft eine künstliche ID. Aus mehreren Spalten = zusammengesetzter Schlüssel.
  • Fremdschlüssel: Spalte, deren Werte im PK einer anderen Tabelle vorkommen müssen.
  • Referenzielle Integrität: Die Datenbank verhindert Verweise ins Leere. Ein Kunde mit Bestellungen kann nicht einfach gelöscht werden (oder wird per ON DELETE CASCADE samt Bestellungen gelöscht).

SQL: Daten ändern (DML)

INSERT INTO Kunde (KundeID, Name, Ort) VALUES (17, 'Müller GmbH', 'Frankfurt');
UPDATE Artikel SET Preis = Preis * 1.05 WHERE ArtikelID = 3;     -- 5 % teurer
DELETE FROM Bestellung WHERE Datum < '01.01.2020';
GRANT SELECT, INSERT ON Bestellung TO vertrieb;  REVOKE INSERT ON Bestellung FROM vertrieb;
FALLE

UPDATE oder DELETE ohne WHERE betrifft alle Zeilen der Tabelle. In der Prüfung gibt es dafür null Punkte.

SQL: Abfragen (SELECT)

SELECT   Spalten / Aggregatfunktionen      -- 5. was ausgeben
FROM     Tabelle                           -- 1. woher
JOIN     Tabelle ON Bedingung              -- 1. verknüpfen
WHERE    Bedingung auf Zeilen              -- 2. Zeilen filtern
GROUP BY Spalten                           -- 3. gruppieren
HAVING   Bedingung auf Gruppen             -- 4. Gruppen filtern
ORDER BY Spalte ASC|DESC;                  -- 6. sortieren

JOINs

JOINErgebnis
INNER JOIN (= JOIN)nur Zeilen mit Treffer in beiden Tabellen
LEFT JOINalle Zeilen der linken Tabelle, rechts NULL, wenn kein Treffer (z. B. auch Kunden ohne Bestellung)
RIGHT JOINalle Zeilen der rechten Tabelle
-- Alle Bestellungen mit Kundenname, neueste zuerst
SELECT b.BestellID, b.Datum, k.Name
FROM Bestellung b
INNER JOIN Kunde k ON b.KundeID = k.KundeID
ORDER BY b.Datum DESC;
-- Kunden ohne Bestellung
SELECT k.Name FROM Kunde k
LEFT JOIN Bestellung b ON k.KundeID = b.KundeID
WHERE b.BestellID IS NULL;
-- Umsatz pro Kunde, nur Kunden über 1.000 €
SELECT k.Name, SUM(p.Menge * a.Preis) AS Umsatz
FROM Kunde k
JOIN Bestellung b ON k.KundeID = b.KundeID
JOIN Position p   ON b.BestellID = p.BestellID
JOIN Artikel a    ON p.ArtikelID = a.ArtikelID
GROUP BY k.Name
HAVING SUM(p.Menge * a.Preis) > 1000
ORDER BY Umsatz DESC;
-- Unterabfrage: Artikel teurer als der Durchschnitt
SELECT Bezeichnung, Preis FROM Artikel
WHERE Preis > (SELECT AVG(Preis) FROM Artikel);
FALLEN
  • Jede Spalte im SELECT, die nicht in einer Aggregatfunktion steht, muss im GROUP BY stehen.
  • Aggregatfunktionen gehören nie in WHERE , sondern in HAVING .
  • Bei JOIN die ON-Bedingung nicht vergessen, sonst entsteht ein kartesisches Produkt (jede Zeile mit jeder).
  • Text und Datum in einfache Hochkommas: 'Frankfurt' , '25.11.2026' .

Datumsformat: Der Katalog-Anhang gibt DATE im Format TT.MM.JJJJ an (z. B. '25.11.2026'); so steht es auch in diesem Kapitel. Echte Datenbanken erwarten meist ISO 'JJJJ-MM-TT' – in der Prüfung gilt das Format der Aufgabe bzw. des Belegsatzes. COUNT(*) zählt alle Zeilen, COUNT(Spalte) nur Zeilen ohne NULL in dieser Spalte (wichtig bei LEFT JOIN). Referenzielle Integrität: ON DELETE CASCADE löscht abhängige Datensätze mit, ON UPDATE CASCADE gibt eine Schlüsseländerung an die Fremdschlüssel weiter. Weiterer Datentyp laut Katalog: Geokoordinaten (Breite/Länge, meist DECIMAL).

Betrieb: Transaktionen, Index, Sicherheit, NoSQL

  • Transaktion (ACID): Atomarität (ganz oder gar nicht), Consistency/Konsistenz, Isolation (parallele Transaktionen stören sich nicht), Dauerhaftigkeit. Beispiel Überweisung: Abbuchung und Gutschrift gemeinsam mit COMMIT , bei Fehler ROLLBACK .
  • Locking: sperrt Datensätze während des Schreibens, damit gleichzeitige Änderungen sich nicht überschreiben.
  • Index: beschleunigt Suchen und JOINs auf einer Spalte deutlich, verlangsamt aber INSERT/UPDATE leicht und braucht Speicher. Sinnvoll auf häufig gesuchten Spalten und FKs.
  • Sicherheit: Rechte per GRANT/REVOKE nach Least Privilege, Prepared Statements gegen SQL-Injection, Backups (Dump oder konsistenter Snapshot, auf getrenntes Medium kopiert), Protokollierung für Nachvollziehbarkeit.
  • NoSQL: ohne festes Tabellenschema, horizontal gut skalierbar. Arten: Dokument (MongoDB), Key-Value (Redis), Graph (Neo4j), Wide-Column (Cassandra).
  • Datenbankanbindung: Anwendungen verbinden sich über standardisierte Schnittstellen wie ODBC oder JDBC (Treiber + Verbindungsdaten: Server, Port, Datenbank, Benutzer). Das Konto der Anwendung bekommt nur die nötigen Rechte.
  • Data Warehouse vs. Data Lake: Ein Data Warehouse sammelt aufbereitete, strukturierte Daten aus mehreren Quellen für Auswertungen (Schema vorher festgelegt). Ein Data Lake speichert Rohdaten jeder Art (auch unstrukturiert), das Schema entsteht erst beim Auswerten.

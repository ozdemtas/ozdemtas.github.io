24Troubleshooting & Log-Analyse

Relevanz ★★★Screenshot-Aufgaben: 4–6 Punkte mit wenig SchreibaufwandLernzeit ca. 90 min
AUF EINEN BLICK
  • Systematisch vorgehen: von unten nach oben im OSI-Modell (Kabel/Link → IP → Gateway → DNS → Dienst/Port → Anwendung).
  • Werkzeuge: ipconfig /all , ping , tracert , nslookup , Test-NetConnection -Port / telnet , netstat / ss , Ereignisanzeige/Logs.
  • Typische Schlüsse: 169.254.x.x → DHCP · IP geht, Name nicht → DNS · Ping geht, Dienst nicht → Port/Firewall/Dienst.

Systematische Fehlersuche

  1. Problem eingrenzen: Wer ist betroffen (ein Nutzer, eine Abteilung, alle)? Seit wann? Was wurde geändert?
  2. Hypothese aufstellen und von unten nach oben prüfen.
  3. Lösung umsetzen, testen, dokumentieren (Ticket, Wissensdatenbank).

2 IP-Konfigurationipconfig /all / ip a169.254.x.x = kein DHCP; falsche Maske oder falsches Gateway
3 Lokales Netzping GatewayVLAN, Switch, Gateway down, IP-Konflikt
4 Entfernte Netzeping externe IP, tracertRouting, NAT, Firewall, Provider

Netzwerkanalyse mit Wireshark und Nmap

Wireshark (Kommandozeile: tshark; unter Linux auch tcpdump) ist ein Paketanalysator (Sniffer): Er zeichnet den Verkehr an einer Schnittstelle auf (Datei .pcap) und zeigt jedes Paket mit allen Schichten (Ethernet, IP, TCP/UDP, Anwendung).

Anzeigefilterzeigt
ip.addr == 192.168.1.10Verkehr von und zu diesem Host
tcp.port == 443HTTPS-Verkehr
dns · dhcp · arp · icmpnur dieses Protokoll (z. B. DHCP-DORA oder DNS-Anfrage und -Antwort)
tcp.flags.syn==1 && tcp.flags.ack==0Verbindungsaufbauten (erstes Paket des 3-Wege-Handshakes)
  • Typische Befunde: SYN → SYN-ACK → ACK = Verbindung klappt · SYN → RST = Port geschlossen, kein Dienst · SYN ohne Antwort, mehrfach wiederholt = Firewall verwirft · viele Retransmissions = Paketverlust/Überlast · lesbare Passwörter bei FTP, Telnet oder HTTP = unverschlüsseltes Protokoll.
  • Mitschneiden im Switch-Netz: Ein Switch leitet nur den eigenen Verkehr und Broadcasts an den Analyse-PC. Für fremden Verkehr braucht man Port-Mirroring (SPAN-Port) oder einen Netzwerk-TAP.

Nmap ist ein Portscanner für Inventarisierung und Sicherheitsprüfung: Welche Hosts sind online, welche Ports offen, welche Dienste laufen?

BefehlZweck
nmap -sn 192.168.1.0/24Ping-Scan: welche Hosts im Netz antworten
nmap -p 1-1024 192.168.1.20bestimmte Ports prüfen
nmap -sV 192.168.1.20Dienste und Versionen auf offenen Ports erkennen
nmap -O 192.168.1.20Betriebssystem schätzen

Portzustände: open (Dienst antwortet) · closed (erreichbar, aber kein Dienst) · filtered (keine Antwort, eine Firewall verwirft). Einsatz: nach einer Härtung prüfen, dass nur die nötigen Ports offen sind, und Firewall-Regeln testen.

FALLE

Mitschneiden und Scannen nur im eigenen Netz und mit Genehmigung: Mitschnitte enthalten personenbezogene Daten (DSGVO, Betriebsrat), und das Scannen fremder Netze kann strafbar sein.

TYPISCHE PRÜFUNGSAUFGABE

Ein Client erreicht den Webserver 192.168.1.20 nicht. Im Wireshark-Mitschnitt sieht man vom Client ein TCP-SYN an Port 443, der Server antwortet mit RST. Was bedeutet das?

Lösung: Der Server ist erreichbar (Routing und Firewall lassen das Paket durch), aber auf Port 443 lauscht kein Dienst. Webserverdienst prüfen (läuft er? richtiger Port?), z. B. mit systemctl status nginx und ss -tulpn.

BefehlZweck

ÜBUNGEN

Ü24.1 Ein Nutzer kann ping 8.8.8.8 erfolgreich ausführen, www.firma.de öffnet sich aber nicht. Nächster Schritt und wahrscheinliche Ursache?

Ü24.2 Ein neuer Webserver antwortet auf ping, die Webseite lädt aber nicht. Wie gehst du vor?

Lösungen Kapitel 24

Ü24.1 nslookup www.firma.de ausführen. IP-Konnektivität funktioniert, also liegt das Problem wahrscheinlich bei der Namensauflösung (falscher/nicht erreichbarer DNS-Server, fehlender Record). Danach ggf. ipconfig /flushdns .

Ü24.2 Port prüfen: Test-NetConnection server -Port 443 bzw. 80. Geschlossen → auf dem Server prüfen, ob der Webdienst läuft ( systemctl status nginx ) und auf welchem Port er lauscht ( ss -tulpn ), Host-Firewall und Netzwerk-Firewall-Regeln prüfen. Port offen → Logs des Webservers, Zertifikat, Konfiguration prüfen.
